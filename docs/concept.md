# Building AI — コンセプト

> 実装仕様は [spec.md](./spec.md) を参照。本ファイルは「なぜ作るか」を記述する。

## 概要

e-Nexus（電気通信大学 東11号館）のビル設備を制御する Web アプリケーションを開発する。
具体的には、e-Nexus のビル設備 API を自然言語で制御するための Web UI である。

本インターフェースでは、照明・空調・換気それぞれを専門とする AI エージェントが相互に会話し、適切なビル設備運用を決定する。
各エージェントは妖怪のようなキャラクター（アイコン）で表現し、アイコン同士がチャットで会話する様子を表示しながら、
どういった理由で現在のビル制御ロジックを実行しているかを利用者に説明する役割を果たす。

## 本アプリケーションの狙い

本学は「共創進化スマート社会」という未来社会の実現を目指している。
この未来社会を実現する重要な要素として、以下の3つの機能が連携し、自律的に循環することでシステムが自律的に進化するという概念がある。

**基本概念**

| 機能 | 内容 |
|---|---|
| 機能1 | あらゆるデータやアクチュエータの NW 連携 |
| 機能2 | 人間知（ヒト）と機械知（AI）の協働による新方式の発見 |
| 機能3 | 未来予測により安全性を保障し社会に実装 |

本 Web アプリケーションは、この概念を実験的に実証するためのシステムとして開発する。

e-Nexus では現在 BEMS（Building Energy Management System）が稼働しており、制御ロジックが確定した製品として動いている。
対して本アプリケーションは、AI を活用して高頻度で動的に制御ロジック（ポリシー）が更新され、
それらが参照するセンサーデータも日々変動することで、より最適な未来社会の在り方を表現したい。

## 基本概念の実現イメージ

対象は電気通信大学の e-Nexus。空調・換気・照明を操作する API と、各種環境センサー（温湿度・CO2・人感・電力量）を取得する API が存在する。

### 機能1：データ収集と NW 連携（完成済み）

データ収集とアクチュエータの API 連携は既に完成しており、Elasticsearch の index を通して参照できる。
→ [spec_datasource.md](./spec_datasource.md), [spec_api.md](./spec_api.md)

### 機能2：ヒトと AI の協働ループ

制御用 AI エージェント（照明・空調・換気）が蓄積データから制御改善仮説を「ポリシー案＋判断根拠」として提案し、
運用者が承認・修正・棄却する協働ループ（説明可能性）を実現する。
AI エージェントは学内 LLM（Qwen 3.5）を利用し、ローカル環境で完結する仕組みとする。
→ [spec_llm.md](./spec_llm.md)

### 機能3：安全性の保障

- (a) **リプレイ検証**：過去データによる効果・悪影響の事前推定
- (b) **ガードレール**：安全制約の強制と即時ロールバック
- (c) **動的実装**：ポリシーの無停止差し替え

→ [spec_api.md](./spec_api.md) 3.6〜3.7

## Web アプリケーション UI 案

Web ブラウザで開き、1画面上に以下を表示する。

- センサー数（種別ごと、1F / 2F / 3F）
- 各エージェントのキャラクター
- エージェント同士の会話画面（チャット風。どんな根拠でロジックを作り出しているかを会話で説明）
- 現在の制御ロジック（ポリシー）の図示：照明 / 空調 / 換気それぞれ
- 各ロジックがどの環境センサーを利用しているか（今回は何を使い、何を使っていないかが分かる）
- 各エージェントとの対話用チャット画面（必要に応じて人間が各エージェントと会話する）
